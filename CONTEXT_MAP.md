# Verdandi -- Context Map

## 1. Purpose

Verdandi ("what is becoming") is a typed composition hierarchy of YAML files organized into 15 levels across 4 tiers. It defines the structural vocabulary for agent definitions -- what fields exist, what types they have, and how they compose into groups, sections, and complete schemas. Verdandi is a data directory, not an executable. Other tools (Draupnir, Regin, Galdr, Nornir, scaffold_definition.py, inspect_schema.py) consume it to generate JSON Schemas, validate agent definitions, and produce platform-specific outputs. This CONTEXT_MAP helps new agents orient to where knowledge about Verdandi lives and helps working LLMs know where to refresh context mid-session.

**Multi-project architecture:** Verdandi uses a shared core with per-project overlays:

- **`core/source/`** — shared immutable Tier 1 types (pattern, atom, enum, element, tuple, union). New primitives always go here.
- **`agent-builder/source/`** — the original project. Tier 1 dirs are symlinks to core. Field through schema are real directories. 13 pipeline schemas.
- **`agent-output/source/`** — configurable rendering surfaces. Same symlink pattern for Tier 1. 3 schemas (structure, content, display).

## 7. Known Issues / Active Work

**Dead types under review:**
- `atom/timestamp_zulu` -- zero consumers anywhere. No field, union, or element references it. Flagged for removal or documented future use.
- `union/string_identifier` -- zero consumers. Provisioned for future use or orphaned after refactor.

**Draupnir enforces sections:/shallowsections: mutual exclusion** at compile time via the `exactly_one_section_type` model validator on the Schema class. A schema file must have exactly one of these keys — neither or both is a validation error.

**pattern/home portability:** The `pattern/home` regex is hardcoded to `/Users/johnny/`. This is a known limitation if definitions are ever used on another machine.

**Schema Zone Unification** (completed — see `PLAN_SCHEMA_ZONE_UNIFICATION.md` for design rationale)

Three changes landed together:
1. **Schema level uses required/optional/conditional zones** — replaced flat map + separate required/nullable lists. Nullable removed (functionally identical to optional).
2. **Presence-based conditionals** — `exists: true` predicate on ConditionalWhen, enabling conditions based on property presence not just value matching.
3. **Leading-dot cross-section paths** — `field: .indirect.dispatch.dispatch_mode` (leading dot) disambiguates root traversal from same-object sibling references.
